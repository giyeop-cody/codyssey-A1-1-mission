# 요약: "RVC 병합해서 쌀먹하기" — 무엇을 만들었고, 무엇이 현실인가

## 1. 요청 → 현실 대조

| 요청 | 판정 | 근거 |
|---|---|---|
| RVC **v2 + v3** 병합 | ❌ **불가능(현재)** | RVC v3 공식 배포가 없습니다. 공식 저장소는 v2(32k/40k/48k)까지이고 v3는 개발 중 상태가 유지됩니다(이슈 #2013, 2026-01 확인). v2↔v3는 아키텍처가 달라 ckpt 텐서가 맞지 않습니다. → **v2끼리 병합**으로 설계했습니다. |
| 게임 대사 + 그 음원 / 가수 음원 + 가사로 학습 | ⚠ **권리 문제가 먼저** | 게임 대사·가수 음원을 긁어 학습한 모델은 복제권·2차적저작물 작성권·퍼블리시티권 문제로 **판매 불가**가 됩니다. 코드는 `consent`가 `self/licensed/synthetic`이 아니면 실행을 거부합니다. |
| 비슷한 특징끼리 묶기 | ✅ **구현·검증** | 9축 음향 실측 → 평균연결 응집 클러스터링 + 실루엣 k 선택(결정론적). |
| 랜덤하게 몇 개 뽑아 순서·개수·비중 랜덤 병합 | ✅ **구현·검증** | 3~5개 추출 → 2~3개를 1:3:2 식으로 → 남은 개수를 1개씩(또는 몰아서) 누적본과 병합. **단계마다 비중·앞뒤 순서 재추첨.** 가중치 트리로 최종 비중을 정확히 계산(손계산 대조 테스트). |
| 노래 4~5곡 + 대사 5~6개 출력 | ✅ 목록 자동 확정 | `plan.json`에 렌더 ID까지 고정. 실제 렌더는 GPU/RVC 필요. |
| GPT 등으로 음색 확인 | ⚠ **다른 방법으로 대체** | LLM은 파형을 듣지 못하고 형용사를 지어냅니다. → **측정값 → 문장 규칙**으로 서술. LLM은 "표에 없는 형용사 금지" 조건의 문장 다듬기에만 선택 사용. |
| 부스에서 판매 | ⚠ **조건부 가능** | BOOTH는 AI 생성물 판매를 금지하지 않지만, 특정 인물·작품 의존 상품과 대량 유사 출품을 제재합니다(2023-05-16, 2025-07-18). 오리지널 캐릭터 음색으로 기획해야 합니다. |

## 3. 검증된 것 / 검증 불가능한 것

**검증됨**
- 220Hz 합성음 → f0 중심 220Hz 복원, 음역·비브라토·밝기·거칠기·어택·비음·숨소리·기복 9축 산출
- 군집·짝짓기·레시피 결정론(같은 시드 = 같은 JSON)
- 가중치 트리 vs 순차 병합 수학 일치(1:3:2 → 0.4 → 0.6 손계산 대조)
- 병합 스크립트를 **가짜 torch로 실제 실행**해 `0.75·A + 0.25·B` 검증
- 게이트(지분·유사쌍·리프 수), 감사(클리핑·무음·운율), 문구 lint(면책 문맥 구분)
- proxy 특징으로는 판매 문구 생성이 **거부**됨

**검증 불가(환경상)**
- 실제 RVC 학습·렌더 품질, 병합 모델의 주관적 음색
- 상업적 수요, 가격 수용도, 플랫폼 심사 결과
