# RVC 음성 병합 → 부스 판매: 실제로 되는 절차

> 이 문서는 요청하신 흐름을 **실행 가능한 순서**로 바꾼 것입니다.
> 코드는 `voice-blend/`에 있고, GPU 없이 돌아가는 부분(특징 측정·군집·레시피·게이트·설명글)은
> 지금 이 저장소에서 **실제 계산으로 검증**했습니다(`artifacts/demo/REPORT.md`, 테스트 44개).
> 모델 학습·렌더는 GPU와 원본 음성이 있어야 하므로 명령과 전제만 고정해 두었습니다.

---

## 0. 먼저 정정해야 할 3가지 (여기서 사고가 갈립니다)

| 요청 | 실제 | 그래서 어떻게 |
|---|---|---|
| **RVC v2 + v3 병합** | RVC v3(공식)는 아직 **배포되지 않았습니다.** 공식 저장소는 v2(32k/40k/48k)까지이고 v3는 "개발 중" 상태가 2026-01 기준 유지 중입니다([이슈 #2013](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/issues/2013)). 일부 포크(Applio 등)가 BigVGAN 기반 v3를 별도로 실험합니다. | **v2 계열끼리만 병합**이 안전합니다. v3가 나오면 "같은 v3끼리" 병합해야 하고, v2↔v3는 아키텍처가 달라 `ckpt merge`가 텐서 형상부터 맞지 않습니다. 이 저장소는 `CheckpointInfo.compatible_with()`로 **샘플레이트·f0 유무·버전·텐서 수**가 다르면 병합을 막습니다. |
| **"학습한 뒤 비슷한 특징끼리 묶고"** | RVC에서 병합은 **가중치 선형결합(Weighted Sum)** 이고, 모델에서 "음색"을 직접 읽어낼 수는 없습니다. | 병합 **전에** 각 음성에서 9개 축(음높이·음역·비브라토·밝기·거칠기·어택·비음·숨소리·음량기복)을 **실측**해 군집화하고, 같은 군집 안에서만 랜덤 경로를 뽑습니다. |
| **"gpt로 음색 확인"** | LLM에게 오디오를 주면 음색을 지어냅니다(측정이 아님). 판매 문구에 지어낸 형용사가 들어가면 그게 곧 환불·분쟁 사유입니다. | 음색 서술은 **측정값 → 문장 규칙**으로 생성합니다(`selling.blend_profile`). LLM은 선택: 측정값 표를 주고 "표에 없는 형용사 금지"로 문장 다듬기만 시킬 때만 씁니다(`prompts/voice_analysis_prompt.md`). |

추가로, **"학습"을 새로 할 필요는 없습니다.** 이미 학습된(또는 판매/배포 허가가 있는)
RVC 모델이 있으면 바로 병합 재료가 됩니다. 새로 학습한다면 화자당 10분 이상 저잡음이
필요하고, 대사/노래를 **같은 원본에서 잘라 쓰면 누출**이 생깁니다(`manifest`의 `shard`로 차단).

## 1. 전체 파이프라인 (코드 대응)

```
[원본 음성]                      [ckpt]                    [병합본]            [산출물]
대사 5~6명, 노래 5~6명  →  RVC v2 학습  →  특징 실측 → 군집 → 풀 → 랜덤 경로 → ckpt 병합 → 렌더 → 감사 → 상품
   (권리 확보)              (10분+/화자)    acoustics    clustering  plan    recipe      merge_recipe  render_track audit_renders selling
```

1. **입력 정리** — 화자별 음성 10분 이상, 대사/노래 각각 최소 5명. 권리는 `self`/`licensed`/`synthetic` 중 하나로 매니페스트에 기록. 같은 원본 조각(`shard`)은 한 번만 사용.
2. **특징 실측** — `scripts/make_manifest.py --audio-dir data/raw --template ...` → 9축 CSV.
3. **군집** — 평균 연결 응집 + 실루엣으로 k 결정(결정론적, 같은 입력=같은 결과).
4. **짝짓기** — 대사↔노래를 음역·밝기 근접도로 1:1 매칭. 병합 모델 하나로 "노래 4~5곡 + 대사 5~6개"를 뽑아야 하므로 풀에 두 종류가 반드시 들어갑니다.
5. **랜덤 경로** — 요청하신 그대로: 3~5개 추출 → 첫 2~3개를 1:3:2 같은 비중으로 → 남은 개수를 1개씩(또는 몰아서) 누적본과 병합. **단계마다 비중·순서를 새로 뽑습니다.**
6. **게이트** — 최대 지분 ≤62%, 최소 ≥3%, 원본 ≤6개, 유사 음성쌍 배제. 떨어지면 재추첨(최대 60회/병합본).
7. **ckpt 병합** — 트리를 리프까지 전개한 최종 가중치로 한 번에 병합(`merge_recipe.py`). 반복 병합보다 dtype 오차가 적습니다.
8. **렌더** — `render_track.py` (RVC WebUI 호출)로 곡/대사 렌더.
9. **감사** — `scripts/audit_renders.py`: 누락·클리핑·무음·f0 점프·모음 시작률 검사. **통과분만** 상품 문구로 넘어갑니다.

## 2. 실행 명령 (GPU 환경에서)

```bash
cd voice-blend
pip install -r requirements.txt          # numpy, pytest (torch는 RVC 환경에 이미 있음)

# 1) 지금 바로 해볼 수 있는 것: 전 과정 데모(합성 음성, GPU 불필요)
python scripts/demo_plan.py              # artifacts/demo/REPORT.md 생성
python -m pytest -q                      # 44 passed

# 2) 실데이터
#    data/raw/<voice_id>.wav 준비 + data/manifests/voices.csv(권리·종류·shard) 작성
python scripts/make_manifest.py --audio-dir data/raw \
    --template data/manifests/voices.csv --out data/manifests/voices.measured.csv
python scripts/build_plan.py --manifest data/manifests/voices.measured.csv \
    --dialogues data/libraries/dialogues.json --songs data/libraries/songs.json \
    --checkpoints data/manifests/ckpt_paths.json --out plan --seed 20261106

# 3) 병합 (RVC 설치 환경)
python plan/merge_recipe.py plan/recipes/<recipe_id>.json --out models

# 4) 렌더 (RVC WebUI 경로 필요)
python plan/render_track.py --repo /path/to/RVC --model models/<recipe_id>.pth \
    --index logs/<exp>/added_*.index --input data/targets/<곡>.wav --output renders/<render_id>.wav

# 5) 감사
python scripts/audit_renders.py --plan plan/plan.json --renders renders/ --out reports/audit
```

`plan/plan.json`은 **무엇을·어떤 비중으로·어떤 파일로 뽑을지** 전부 고정합니다. 시드 하나만
남기면 결과를 완전히 재현할 수 있고, 이게 판매 상품의 "재현 정보"가 됩니다.

## 3. 판매 전 체크리스트 (이게 실제 병목입니다)

**데이터·권리**
- [ ] 학습 음성의 권리 상태: 본인 / 정식 라이선스 / 합성. 게임 대사·가수 음원을 **그냥 긁어 학습하면** 판매 불가(복제권·2차적저작물 작성권·퍼블리시티).
- [ ] 원본 오디오 파일은 상품에 포함하지 않는다(모델만).
- [ ] 실존 인물 이름·사진·로고를 상품 페이지에 쓰지 않는다(퍼블리시티권).
- [ ] `consent` 값이 `self|licensed|synthetic`이 아니면 파이프라인이 **실행을 거부**합니다.

**플랫폼(BOOTH 등)**
- [ ] BOOTH는 AI 생성물 판매를 금지하지 않지만, **특정 작품·인물에 의존적인 상품**과 그 **대량·연속 출품**은 제재합니다(2023-05-16, 2025-07-18 공지).
      → "그 가수 목소리 재현" 같은 상품은 2025-07 강화 조항의 표적입니다. **오리지널 캐릭터 음색**으로 기획하세요.
- [ ] 같은 제작 방식의 유사 상품을 수십 개 올리면 전체가 검색에서 빠질 수 있습니다.
- [ ] 개인용/상업용 라이선스를 분리하고, 가격 차등(관행 3~5배)을 명시.

**표시 의무(한국)**
- [ ] AI 기본법(2026-01-22 시행) 제31조: 생성형 AI 결과물임을 이용자가 알 수 있게 **고지·표시**.
      → 상품 페이지 상단 고지 + 렌더 파일에 "AI 생성" 표기. 1년 이상 계도 기간이지만 지금부터 하는 게 안전합니다.
- [ ] 가이드라인상 게임·영상처럼 몰입형 콘텐츠는 시각적 표시 예외가 있으나, **실존 인물 오인 우려가 큰 경우는 예외 없음**.

**품질**
- [ ] 노래 4~5곡 + 대사 5~6개 **전부** 감사 통과(`audit_renders.py` 종료코드 0).
- [ ] 구성 비중·병합 경로를 상품 페이지에 공개(재현 가능 = 환불 분쟁 방어).

## 4. 상품 페이지 템플릿

`artifacts/demo/product_*.md`가 실제 생성 예시입니다. 구조:

1. **상단 고지** — AI 음성 모델 / 실존 인물 아님 / 학습 데이터 권리 상태
2. **한 줄 소개** — 중심 음성 + 비중 (예: "중심 50%, A 33%, B 17%")
3. **음색 요약** — 측정된 9축을 쉬운 말로(중심 음높이 Hz, 음역 반음, 비브라토 Hz, 밝기·거칠기·어택 구간, 숨소리…)
4. **어디에 쓰면 좋은가** — 측정에서 유도(자음 또렷 → 대사/내레이션, 비브라토·기복 → 노래 커버)
5. **구성 비중(재현용)** + 병합 트리 JSON
6. **감사 결과** — 렌더별 통과/주의
7. **라이선스** — 허용/금지 항목, 재배포 금지, AI 표시
8. **가격** — 개인/상업 분리

가격 가이드(`selling.price_tiers`): `12,000원 + 곡 3개 초과당 1,200 + 대사 4개 초과당 600`,
상업용 ×3.5. 재료 수·경쟁·플랫폼 수수료에 따라 조정하는 **기준선**입니다.

## 5. 자주 깨지는 지점과 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 병합 후 목소리가 "두 사람"처럼 들림 | 음역이 다른 모델을 섞음 / 지분 20% 미만 파편이 여럿 | 게이트가 1차 차단(최소 3%, 유사쌍 배제). 남으면 비중 상위 2개만 남기고 재병합 |
| 음정이 흔들리거나 튐 | f0 유무·sr 다른 모델 병합 | `compatible_with()`로 사전 차단. 렌더 감사의 `f0_jump_ratio` > 20%면 재렌더 |
| 대사는 되는데 노래가 안 됨 | 풀에 노래 비중이 낮음 | `_kind_balance`가 song/speech 최소 비중을 보상, 첫 단계에 노래 포함 |
| 같은 결과만 나옴 | 순수 난수 경로 | 경로 목표 길이(`route_preferences`)로 한 런에 1~4단계를 섞어 뽑음 |
| 인덱스(.index) 미포함 문의 | RVC는 모델+인덱스 세트로 씀 | 인덱스는 모델에서 파생(재배포 금지 대상) → 포함하되 "재판매 금지" 명시 |
| 문구가 위험 표현으로 반려 | "실제 가수 목소리 재현" 류 | `analysis.lint_copy`가 면책 문맥을 구분해 위반만 표시 |
| 결과가 재현 안 됨 | 시드·비중 미기록 | `plan.json`에 시드·트리·가중치 고정(이미 구현) |

## 6. 지금 검증된 것 / 아직 아닌 것

**검증됨(이 저장소에서 실제 실행)**
- 9축 음향 측정: 220Hz 합성음 → `f0_center` 220Hz 근처 복원(테스트)
- 결정론적 군집·짝짓기·레시피: 같은 시드 = 같은 계획(JSON 문자열 비교 테스트)
- 가중치 트리 계산: 1:3:2 → 0.4 → 0.6 체인을 손계산과 대조(pytest)
- 병합 스크립트 수학: 가짜 torch로 **실제 실행**해 `0.75·A + 0.25·B` 검증
- 게이트/감사/문구 lint 동작, 데모 리포트 생성(`artifacts/demo/REPORT.md`)

**검증 안 됨(환경상 불가)**
- 실제 RVC 학습·렌더 품질, 병합 모델의 실제 음색 주관 평가
- 상업적 수요·가격 수용도
- 각 플랫폼 심사 결과

**다음 단계 제안**: ①권리 확보된 음성 2명(대사+노래)로 최소 파이프라인 1회 통과 →
②병합본 3개 렌더 → ③감사 통과율·청취 메모 기록 → ④그 결과로 가격·상품 수 확정.
