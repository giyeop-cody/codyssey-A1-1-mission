# LLM 보조 프롬프트 (선택 사항)

## 왜 필요 없는 게 기본인가

음색 서술은 `selling.blend_profile()`이 **측정값 → 문장 규칙**으로 만든다. 이건 재현되고,
검증 가능하고, 거짓말을 하지 않는다. 반면 "오디오를 주고 음색을 물어보는" 방식은
LLM이 파형을 실제로 듣지 못하므로 **그럴듯한 형용사를 지어낸다.** 그 문장이 상품 페이지에
들어가면 곧 환불·분쟁 사유가 된다.

LLM을 쓸 곳은 딱 두 가지다.

1. **문장 다듬기** — 측정표를 주고, 표에 없는 형용사는 쓰지 말라고 못 박는다.
2. **타깃 대본/가사 작성** — 짧은 대사 세트, 곡 가사 초안.

아래 프롬프트는 그 두 용도로만 쓴다.

---

## A. 음색 문장 다듬기 (측정값 고정)

```text
너는 음성 상품 상세페이지 카피라이터다. 아래 [측정값]은 실제 오디오에서 계산된 값이다.
규칙:
1. [측정값]에 없는 형용사·비유·품질 보증("미친 퀄리티", "완벽 재현")을 쓰지 마라.
2. 실존 인물·아티스트·작품 이름을 쓰지 마라.
3. 각 문장은 어떤 측정값에서 나왔는지 괄호로 표시하라. 예: "밝고 앞으로 나오는 톤(밝기 0.61/1.0)"
4. 9개 축을 모두 다루되, 3개는 "이런 용도에 적합" 형태로 연결하라.
5. 출력은 한국어 마크다운, 25줄 이내.

[측정값]
- 중심 음높이: {f0_center_st} 반음 (C3=0, 약 {f0_hz}Hz)
- 음역 폭: {f0_range_st} 반음 (5~95퍼센타일)
- 비브라토: {f0_vibrato_hz} Hz
- 밝기: {brightness} / 1.0
- 거칠기(스펙트럼 평탄도): {roughness} / 1.0
- 자음 또렷함(어택): {attack} / 1.0
- 비음: {nasality} dB (2.5~4kHz − 0.5~1kHz)
- 숨소리: {breathiness} / 1.0
- 음량 기복: {expressiveness} dB (5~95퍼센타일)

[구성]
- 병합 원본 {n}개, 최종 비중 {weights}
- 렌더 감사: 곡 {song_pass}/{song_total} 통과, 대사 {line_pass}/{line_total} 통과
```

## B. 타깃 대본·가사 생성

```text
아래 조건으로 RVC 음성 변환용 타깃 대본을 만들어라.
- 목적: {장르/상황}
- 톤: {tone}
- 길이: 대사는 1.5~4초 분량(한 문장), 노래 가사는 Verse/Chorus 8줄 이내
- 금지: 실존 작품·가수·게임 대사의 원문 인용, 실존 인물 이름, 정치·혐오 표현
- 출력: JSON 배열 [{"id": "...", "text": "...", "seconds": 추정, "tone": "..."}]
- 각 항목은 서로 다른 감정 축(체념/분노/다정/조급/회복 …)을 하나씩 담아라
```

생성 결과는 `data/libraries/dialogues.json` / `songs.json`으로 저장한 뒤
`analysis.lint_violations()`로 한 번 더 검사한다(대본 자체는 lint 대상이 아니지만,
상품 페이지에 그대로 복사될 수 있으므로 습관화).
